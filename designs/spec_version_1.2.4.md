## Network-share robustness (review 2026-10-30)
From Greg's three questions: SMB client caching ("does the lock file exist?" can return an old answer), antivirus /
indexers / backup and sync agents holding the shared file at the moment of the rename, and renames that are not atomic
on some NAS boxes and cloud gateways. Read-only review against the code; nothing was changed. **Verdict:** nothing found
can lose data or let two people write at once. The lock is taken by an atomic create (`FileMode.CreateNew`,
`WriteLockService.cs:987`), uploads are hash-verified before the rename, and every open runs `integrity_check` on the
local copy. The gaps are failed saves and wrong messages (rule 4), plus one kind of storage the design cannot protect.
**Rules check for the fixes:** none touches D' or the dirty marker (rule 3); NS1 makes the lock check stricter and NS4
must be cancellable (rule 2); NS6 extends rule 1's "checked" to the reader's copy. `MinimumVersionToWrite`: No for all
(nothing new is saved). NS4 and NS7 change the save path: risk review first (Alice-and-Bob).

| Ref | What | Notes |
|---|---|---|
| NS1 | **Lock checks still start with an existence test**, which Windows can answer from its client cache (file-not-found results ≈5 s, file info ≈10 s). ## Faster release testing (from the 1.2.3 field tests, 2026-11-01)
The 1.2.3 field tests (`docs/testing/network-field-tests-1.2.3.md`) ran about 8 hours on 22 Oct and 10 on 27 Oct
(log timestamps), plus the morning of 28 Oct. Comparing them with the harness (`src/TermPoint.Tests/Harness/`) and the
probe (`tools/NetworkProbe`): nearly every field finding came from something the harness simulates more kindly than
reality (the share, timing, clocks, the UI, the process, other versions). So: first close the harness gaps (H), so
those bugs turn up in the automated run; then make the hand tests that remain cheaper (T).
**Rules check:** H1–H6 and T2–T5 are test code and tooling only: no rule touched, `MinimumVersionToWrite`: No. T1
changes lock-timing code: production values must stay identical, and rule 2 is the risk (story in T1): risk review
